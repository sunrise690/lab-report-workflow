# 实验文件归档

用于“整理实验文件夹”“整理实验7到12”“归档实验报告”等请求。目标是让用户找到当前报告、原始资料和编辑入口，不改报告内容，不新增数值分析。

## 先核对归属与版本

在用户指定范围内查看文件名、目录、报告题目和源文件关系。资料可能散在实验目录、output、outputs和旧工作区中。编号须与实验题目共同确认，同名编号下的不同主题分开标记；公共讲义、其他实验和参考报告不冒充该实验的原始记录或当前报告。

“当前版本”以用户最近确认、实际修改内容和活动源码为依据。文件名中的“最终版”、最新修改时间或最大文件体积只能作为线索。需要聊天记录时，只提取相关用户更正和最终交付消息，避免输出工具日志。若存在多个用途相同但无法判断先后的版本，保留原名并注明待确认；这不妨碍整理其他文件。

已有活动源码生成的PDF时，用SHA256与候选报告核对，确认两者是否为同一修订。缺少对应PDF时记录“未核对”，不为文件归档重新编译。正式版、抄写版和源包分别核对，不能因其中一个时间较新就推定其余文件也是最新版。

## 目录与入口

优先沿用已建立的实验目录和编号。首次归档可采用：

```text
实验名称/
  00_使用说明.txt
  01_当前报告/
  02_原始资料/
  03_源码与数据/
  04_历史版本/
  05_预习与过程/
```

这是一种默认布局，不强制改写用户已有的有效结构，也不为不存在的材料创建空分类。多实验整理时可增加一个总目录说明，列出各实验题目、当前版本和使用入口。当前目录中只放明确选定的版本；不同打印用途要在文件名或说明中区分。

## 移动前检查依赖

检索源码、计算脚本和打包脚本中的绝对路径、相邻目录引用、原始数据默认路径及跨实验依赖。数据表也可能被脚本作为固定输入或输出。

- 没有路径依赖的独立报告、ZIP和预习资料可以移动归类。
- 有固定路径依赖的源码或数据，通常保留原址，在对应分类放Windows `.lnk` 快捷入口。快捷方式的目标必须是本机实际存在的完整路径。
- 当前报告适合直接打开时，可复制到“当前报告”，保留源工作区的生成文件；核对副本哈希，并在说明中标记其来源和后续同步方式。
- 不把快捷入口说成自包含源包。用户需要迁移项目或可独立重建的源包时，另行整理相对路径、依赖和重建入口，并验证新的位置。

不要因为整理文件就重构计算代码、改数据、解包所有压缩文件或重新编译报告。若已有任务仍在写入某个文件，先整理与它无关的材料，避免移动正在生成的目标。

## 保留与核验

整理不默认删除历史版本、相似照片、重复文件或缓存。完全相同的图片也可能因文件名承担不同的实验对应关系，应保留语义。也不覆盖已有同名但内容不同的文件。

移动、复制前后核对文件大小和SHA256；迁移整个目录时，记录相对路径与逐文件哈希，并核对文件数量。Windows移动目录前确认源与目标的绝对路径均在本次整理范围内。

记录实际操作的源路径、目标路径、操作类型和哈希，保留能追溯移动关系的清单。最终检查：当前报告和源包存在、分类没有遗漏已选文件、快捷入口可访问；有多个修订包时核对各组文件齐全。仅改变存放位置且哈希不变的PDF无需重新逐页渲染。

交付时给出总目录或当前报告的直接链接，说明哪些工作区通过快捷入口访问。归档说明不要携带无关聊天内容、临时工具日志或未经证实的版本结论。
